# 카카오 로그인 연결

## 실행

프런트엔드와 백엔드 서버를 모두 재시작합니다.
프런트엔드 환경 변수: KAKAO_CLIENT_ID, KAKAO_CLIENT_SECRET, NEXTAUTH_SECRET, NEXTAUTH_URL, BACKEND_API_URL.
백엔드 환경 변수: KAKAO_APP_ID (카카오 앱 숫자 ID), 기존 JWT/DB 설정.
현재 로컬 설정: NEXTAUTH_URL=http://localhost:3000, BACKEND_API_URL=http://localhost:8080/api.
키와 세션 비밀값은 .env에만 보관합니다.

## 데이터베이스

백엔드에서 npm run db:migrate:kakao 실행. 현재 로컬 DB에는 적용했습니다.
기존 email 컬럼은 유지하고 없는 DB에서만 추가합니다.
provider_subject와 공급자별 사용자 ID 고유 인덱스를 추가하고 KAKAO 공급자를 준비합니다.
테이블 삭제나 전체 synchronize는 실행하지 않습니다. 신규 DB의 db:init에도 KAKAO 공급자가 포함됩니다.
원격/운영 DB에는 별도로 마이그레이션을 적용해야 합니다.

## 흐름

1. 로그인 버튼 → NextAuth 카카오 인증 → /auth/kakao.
2. 서버 API /api/auth/kakao가 암호화된 NextAuth JWT의 카카오 액세스 토큰을 백엔드에 전달합니다. 카카오 토큰은 클라이언트 세션 응답에 노출하지 않습니다.
3. 백엔드는 카카오 토큰의 앱 ID/만료와 사용자 정보, 인증된 이메일을 검증합니다.
4. 등록된 공급자+카카오 사용자 ID가 있으면 기존 일반 로그인과 동일한 서비스 JWT를 반환합니다.
5. 기존 OAuth 행에 사용자 ID가 없다면 공급자+카카오가 검증한 이메일로 연결합니다. ID가 다른 계정을 이메일만으로 자동 로그인시키지 않습니다.
6. 미가입자는 /join/social로 이동합니다. 카카오 닉네임·이메일은 읽기 전용, 이름·전화번호는 입력 가능합니다.
7. 가입 시 백엔드가 다시 카카오 정보를 조회합니다. 클라이언트가 닉네임/이메일을 바꿔 보내도 가입 정보로 사용하지 않습니다.
8. member, oauth_member, 가입 쿠폰을 트랜잭션으로 저장하고 바로 로그인합니다.

## 카카오 동의항목

카카오의 profile_nickname과 account_email을 사용합니다. 실제 이름(name) 제공 권한은 필요하지 않습니다.
2026-09-26 commerce 앱(960004)에서 닉네임은 필수 동의, 이메일은 선택 동의로 확인했습니다.
이메일 제공에 동의하고 인증된 이메일이 있어야 가입할 수 있습니다.
가입 화면의 닉네임과 이메일은 수정 불가이며, 이름과 전화번호는 사용자가 입력합니다.
현재 회원 테이블의 닉네임은 최대 10자이며 고유해야 합니다. 길이가 초과하거나 중복되면 카카오 프로필에서 변경 후 다시 로그인하도록 안내합니다.
기존 회원은 저장된 서비스 프로필을 유지합니다.

공식 응답 필드: https://developers.kakao.com/docs/ko/kakaologin/rest-api

## 검증

백엔드 SQL.js 통합 테스트에서 신규 회원 분기, 가입·쿠폰·JWT 발급, 기존 로그인, 재가입 요청,
다른 앱의 토큰, 이메일 미인증, 닉네임 누락, 클라이언트 닉네임/이메일 위조, 계정 혼동, 탈퇴 계정을 검증합니다.
실제 카카오 응답은 테스트에서 모의 처리하며 실제 카카오 로그인 완료는 별도 확인이 필요합니다.
